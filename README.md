# Реестр обращений по персональным данным

Внутренняя система для DPO: приём обращений субъектов персональных данных и
Роскомнадзора, контроль сроков по **ст. 14, 20 и 21 Федерального закона
от 27.07.2006 № 152-ФЗ**, автоматическая квалификация обращений, распознавание
вложений и подготовка драфтов ответов по вашим типовым формам.

---

## Что умеет

**Реестр и сроки**
* Автоматический расчёт срока по типу обращения с учётом производственного
  календаря РФ (переносы выходных из постановлений Правительства).
* Все контрольные точки, а не одна дата: у требования об уточнении это
  блокирование с момента обращения + 7 рабочих дней на уточнение; у отзыва
  согласия — 30 календарных дней на прекращение обработки и 10 рабочих дней
  на ответ субъекту.
* Каждая дата подписана нормой, из которой она взята.
* Срок из документа (предписание, запрос госоргана) переопределяет расчётный.
* Продление на 5 рабочих дней — отдельным флажком, с напоминанием, что оно
  правомерно только при мотивированном уведомлении.

**Фильтры**
Срочность · тип обращения · вид субъекта (работник, бывший работник, кандидат,
пользователь, потребитель, представитель контрагента) · кто обращается ·
статус · **почтовый ящик, на который пришло обращение** · **юридическое лицо** ·
**сервис или бизнес-процесс** · флажки · даты · полнотекстовый поиск.

**Флажки**
* 🔴 **Красный** — обращение очевидно не про персональные данные: предложение
  о сотрудничестве, потребительская претензия, техподдержка, резюме, счета, спам.
* 🔵 **Синий** — спорный момент, требующий решения DPO: представитель без
  доверенности, нет идентификации по ч. 4 ст. 14, отзыв согласия при наличии
  иного основания обработки, конфликт требования об уничтожении со сроками
  хранения, составное обращение, запрос данных третьего лица, документ «от РКН»
  с чужого домена.

Каждый флажок снимается с описанием принятого решения — запись остаётся
в истории обращения.

**Работа с документами**
Текст, PDF (с текстовым слоем и сканы), фотографии, DOCX, XLSX, EML —
всё приводится к тексту. Для PDF сначала читается текстовый слой, и только
при его отсутствии включается OCR. Распознанный текст можно поправить руками,
после чего обращение переразбирается.

**Ответы**
Загрузите свои типовые ответы (DOCX / PDF / TXT) — система найдёт в них
плейсхолдеры, подберёт подходящий шаблон под конкретное обращение, подставит
реквизиты и **правильные** даты, соберёт чек-лист проверок перед отправкой.
Незаполненные поля остаются видимыми в тексте и выводятся отдельным списком.

## Запуск

```bash
git clone <репозиторий> && cd dpo

# распознавание фотографий и сканов (Ubuntu/Debian)
sudo apt-get install -y tesseract-ocr tesseract-ocr-rus poppler-utils
# macOS: brew install tesseract tesseract-lang poppler

SEED=1 ./run.sh
```

Откройте **http://127.0.0.1:8000**. Ключ ИИ не нужен: классификация, сроки,
флажки, OCR и драфты по шаблонам работают полностью автономно.

Через Makefile:

```bash
make install     # зависимости
make reset       # база с демонстрационными данными
make run         # сервер с автоперезагрузкой
make test        # тесты
```

### Ежедневный пересчёт

Срочность зависит от текущей даты, поэтому раз в сутки нужно дёрнуть пересчёт:

```cron
5 6 * * * curl -fsS -X POST http://127.0.0.1:8000/api/maintenance/recalculate
```

### Подключение ИИ (необязательно)

Скопируйте `.env.example` в `.env` и задайте `ANTHROPIC_API_KEY`. ИИ **уточняет**
результат правил, но никогда не считает сроки — их всегда считает движок
на основе таблицы норм.

### Приём почты

Справочники → Почтовые ящики → укажите IMAP-сервер и **имя переменной
окружения** с паролем (сам пароль в базе не хранится). Затем
`POST /api/inboxes/{id}/sync` забирает непрочитанные письма вместе с вложениями.

## Нормативные сроки

| Тип обращения | Срок | Норма |
|---|---|---|
| Доступ к своим ПД, подтверждение факта обработки | 10 рабочих дней (+5 при мотивированном продлении) | ст. 14 ч. 3, ст. 20 ч. 1–2 |
| Уточнение (исправление) ПД | блокирование с момента обращения; 7 рабочих дней на уточнение | ст. 21 ч. 1–2, ст. 20 ч. 3 |
| Блокирование | блокирование с момента обращения; 7 рабочих дней на решение | ст. 21 ч. 1, ст. 20 ч. 3 |
| Уничтожение ПД | 30 дней; уведомление — 10 рабочих дней | ст. 21 ч. 4 |
| Отзыв согласия | 30 дней на прекращение; ответ — 10 рабочих дней | ст. 21 ч. 5, ст. 9 ч. 2 |
| Прекращение обработки для продвижения | немедленно | ст. 15 ч. 2 |
| Неправомерная обработка | блокирование сразу; 3 рабочих дня на прекращение; 10 рабочих дней на уничтожение | ст. 21 ч. 1, ч. 3 |
| Возражение против автоматизированного решения | 30 дней | ст. 16 ч. 3 |
| Запрос Роскомнадзора | 10 рабочих дней (+5 при мотивированном продлении) | ст. 20 ч. 4 |
| Предписание РКН, уведомление о проверке | **срок из документа** | ФЗ-248 |
| Инцидент (утечка) | 24 часа на уведомление, 72 часа на результаты расследования | ст. 21 ч. 3.1 |

Расчёт: течение срока начинается со следующего дня после события (ст. 191 ГК РФ);
если окончание приходится на нерабочий день, срок переносится на ближайший
следующий рабочий (ст. 193 ГК РФ).

## Что требует вашего внимания

1. **Производственный календарь** — `backend/app/data/production_calendar.json`
   содержит 2024–2026. Календарь на следующий год утверждается постановлением
   Правительства осенью; пока его нет в файле, система считает по правилу
   «суббота/воскресенье + ст. 112 ТК РФ без переносов» и **явно помечает такой
   расчёт как приблизительный** — и в карточке, и в боковой панели.

2. **Дата начала течения срока.** Если запрос не содержит сведений по ч. 4
   ст. 14 (реквизиты документа, удостоверяющего личность, и подтверждение
   отношений с оператором), позиция «срок течёт с даты надлежащего запроса»
   спорна. Система показывает обе даты и ставит синий флажок; отметка
   «личность подтверждена» переносит начало отсчёта на дату подтверждения.

3. **Срок из документов РКН** приоритетнее расчётного и проставляется вручную —
   система об этом предупреждает и подсказывает дату, найденную в тексте.

4. **Потребительские претензии** помечаются красным флажком как непрофильные,
   но если в том же письме есть требование по ФЗ-152, флажок становится синим:
   составное обращение нельзя закрыть как «не наше».

## Устройство

```
backend/app/
  domain.py           типы обращений, виды субъектов, таблица сроков со ссылками на нормы
  calendar_ru.py      производственный календарь РФ, арифметика рабочих дней
  deadlines.py        расчёт контрольных точек и срочности
  classifier.py       правила квалификации и флажков (работают без сети)
  extraction.py       PDF / фото / DOCX / XLSX / EML → текст
  drafting.py         подбор типового ответа, плейсхолдеры, чек-лист
  llm.py              необязательный ИИ-слой поверх правил
  services.py         приём обращения, разбор, пересчёт, журнал
  routers/            HTTP API
frontend/             интерфейс без сборки (нативные ES-модули)
```

Подробнее — в [ARCHITECTURE.md](ARCHITECTURE.md). Документация API:
**http://127.0.0.1:8000/docs**.

## Оговорка

Система помогает соблюдать сроки и не заменяет юридическую оценку. Итоговая
квалификация обращения и содержание ответа остаются за ответственным за
организацию обработки персональных данных.
